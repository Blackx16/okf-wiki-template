How to build a knowledge base that both humans and AI can actually trust

When you ask an to summarize articles into a normal folder of notes, it quickly creates a mess: sources get lost, pages get duplicated, and conflicting facts silently overwrite one another.

The Wiki Template fixes this without locking your notes inside a complex database. It uses ordinary text files, standardized index cards, and two lightweight Python scripts to turn a plain folder into a self-auditing .

Why normal AI notes break down—and how "Metadata as Code" fixes them

Imagine hiring a fast-reading assistant to summarize every article, PDF, and video you watch. If that assistant writes freeform paragraphs on blank pages, your folder feels helpful for the first ten notes. By note #100, you have a pile of disconnected sticky notes: you cannot tell which claim came from which article, and the assistant has to re-read the entire pile every time you add something new.

This repository solves that problem using . Every note is still a human-readable file, but the top of the file carries a standardized index card () that declares what the page is, where its facts came from (), and which other pages it connects to.

As Andrej Karpathy observed when pioneering the LLM Wiki concept: "LLMs don't get bored, don't forget to update a cross-reference, and can touch 15 files in one pass." What was missing was not another closed database service, but an open format. Just as standardized external tool calling and SKILL.md standardized reusable instructions, OKF standardizes shared memory representation and graph bundling.

How the four-layer Knowledge Graph is organized

Instead of dumping raw articles and AI summaries into the same folder, the template separates your vault into four clear layers. Raw originals in raw/ are strictly —the AI reads them but never edits them. From each raw file, the AI builds a reading note in wiki/sources/, and then weaves cross-cutting ideas into wiki/concepts/ and wiki/entities/ using both YAML related: [] lists and clickable .

What happens when two sources disagree?

In a normal AI wiki, when a newer article contradicts an older article, the AI silently overwrites the old sentence—erasing history without telling you.

In OKF, the agent is forbidden from silently overwriting claims. Instead, it keeps both claims and inserts a which wiki_health_check.py immediately highlights in your health report so you can decide what is true.

# Inside a Concept or Entity page:
> [!contradiction]
> Source A ([[2024-benchmark]]) states context windows over 100k degrade recall by 18%.
> Source B ([[2026-retrieval-study]]) reports YAML links maintain 99.4% recall up to 200k tokens.

How OKF compares to a Normal LLM Wiki, Vector Databases (RAG), and Graph Databases

When people want AI to answer questions from their documents, they usually hear about three options: letting an AI write freeform notes, setting up a for , or running an enterprise like Neo4j. Each tool was built for a different job. Here is how they actually work in plain English.

1. Normal LLM Wiki

AI writes freeform Markdown summaries without strict schemas or Python link checkers.

The catch: Easy to start on day one, but without mandatory type: and sources: fields, the AI quickly creates orphan notes, forgets where facts came from, and burns money re-reading files.

2. Vector Database ()

Chops documents into fragments and converts them into math coordinates ().

The catch: Great for searching 500,000 customer support tickets by keyword vibe, but terrible at seeing the big picture. Humans cannot open a Vector DB to read or fix a wrong connection, and chopped paragraphs lose their surrounding context.

3. Enterprise Graph DB (Neo4j / RDF)

Stores nodes and edges inside a dedicated database server queried with .

The catch: Built for massive corporate fraud detection or supply chains with millions of nodes. For personal or team knowledge, running a database server means you can no longer just open your notes in or edit a paragraph by hand.

4. OKF Wiki Template (This Repo)

Plain Markdown files + strict YAML index headers + zero-cost Python graph scripts.

The sweet spot: You get the explicit connections and auditability of a Knowledge Graph, while every single note remains a plain text file you own, read in Obsidian, and track with .

Enterprise software backends with millions of live transactional relationships.

How the automated pipeline processes your files without wasting AI tokens

One of the smartest design choices in this repository is that the AI does not do the clerical work. If you ask an AI to check 300 files for broken links or figure out which articles are new, you pay for tens of thousands of on every single run.

Instead, this template pairs the AI with two fast, Python scripts that cost $0 to run. One script prepares the exact to-do batch before the AI wakes up, and the second script inspects the AI's work after it finishes.

Step 1 · You AI Token Cost: 0

Initialize the vault & drop files into raw/

Run setup.py once to create your folder tree (raw/articles, raw/papers, raw/youtube, etc.), configure adapters, and generate run_daemon.sh. Whenever you find an article, PDF, or note you want to keep, drop it into raw/.

python3 setup.py
# Then drop files into:
raw/articles/my-note.md
Step 2 · Python Script AI Token Cost: 0

The "Mail Sorter" plans a safe batch (wiki_auto_ingest_manifest.py)

Before the AI reads anything, this script scans raw/ and wiki/sources/. It fingerprints each file with a , spots which raw files are new_or_disconnected or missing_body_backlink, estimates their token length, plans for huge files, and packs them into batches that safely fit the AI's .

python3 wiki_auto_ingest_manifest.py
# Outputs JSON manifest:
"actionable_count": 1,
"batches": [ ... ]
Step 3 · AI Agent Bounded to Batch #1

The OKF Enrichment Agent synthesizes notes

Triggered manually or on a timer () via run_daemon.sh, the AI reads AGENTS.md and system-context.md. If actionable_count is 0, it immediately stops. Otherwise, it processes batches[0]: creating source notes in wiki/sources/, updating concepts and entities in wiki/concepts/ and wiki/entities/, and logging its work in log.md.

./run_daemon.sh
# Uses templates/source-page.md
# Appends to log.md
Step 4 · Python Linter AI Token Cost: 0

The "Health Inspector" audits the whole graph (wiki_health_check.py)

Right after ingestion, this script walks every file in wiki/ and checks five quality rules: (pages with 0 incoming links), Broken Links (links pointing to non-existent pages), (< 100 words or > 90 days old), and unresolved .

python3 wiki_health_check.py
# Writes reports to:
wiki/queries/vault-health-summary.md
Step 5 · Git History 100% Reversible

Safe snapshot in

Once log.md and the health reports are updated, the agent commits the changes with a clear [ingest] commit message. Because everything is plain text in Git, you can inspect every line changed or roll back anytime.

git commit -m "[ingest] Add OKF spec"
